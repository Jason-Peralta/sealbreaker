# pack/ — the modpack players install

A [packwiz](https://packwiz.infra.link/) pack: a git-friendly TOML description of the pack (Minecraft 26.2, NeoForge 26.2.0.76, our five mods, the three library mods) that packwiz-installer keeps up to date on every client launch and on the server. Players install exactly one thing.

## What is here

| File | Meaning |
|---|---|
| `pack.toml` | Name, version, Minecraft and NeoForge versions, the index hash |
| `index.toml` | Every file of the pack with its hash; regenerated by `packwiz refresh` |
| `mods/*.pw.toml` | One metadata file per mod: download URL, hash, side, and for Modrinth mods the project and version ids (`geckolib`, `curios`, `jei`); ours (`sb-*.pw.toml`) point at the jars of a GitHub release |
| `.packwizignore` | Files under `pack/` that are not part of the pack (this README, `server/`) |
| `server/start.sh` | A throwaway dedicated server that installs NeoForge and syncs the pack |

`pack/.packwiz/` (local cache) stays ignored by git.

## Editing the pack

The packwiz binary is a GitHub Actions artifact of `packwiz/packwiz` (no releases): `gh run download <run id> --repo packwiz/packwiz -n "Windows 64-bit" -D ~/tools/packwiz`, or the same through https://nightly.link/packwiz/packwiz/workflows/go/main. It lives outside the repository (`C:\Users\<you>\tools\packwiz\packwiz.exe` here). Then, in this directory:

```bash
packwiz modrinth add <slug>              # a library mod from Modrinth (decision 0015: utilities only)
packwiz url add sb_core https://github.com/Jason-Peralta/sealbreaker/releases/download/v0.0.1/sb_core-0.0.1.jar
packwiz refresh                          # after any manual edit; recomputes the index hashes
packwiz update --all                     # bumps Modrinth mods to their latest version for 26.2
packwiz serve                            # serves the pack at http://localhost:8080/pack.toml for local testing
```

Our jars come from a GitHub release: tag the repository (`v0.<milestone>.<build>`, decision 0011), `gh release create <tag> */build/libs/sb_*-<version>.jar`, then re-add the five URLs (or edit the `sb-*.pw.toml` files' `url`, `filename` and `hash` and refresh). The v0.0.1 pre-release holds the Milestone 0 spike builds; Milestone 1 replaces it and CI takes over the upload.

## Installing the pack

**Client (Prism Launcher).** Create a NeoForge 26.2 instance (NeoForge 26.2.0.76). Put `packwiz-installer-bootstrap.jar` (https://github.com/packwiz/packwiz-installer-bootstrap/releases/latest) in the instance's `minecraft` folder and set the instance's pre-launch command (Edit > Settings > Custom commands) to:

```
"$INST_JAVA" -jar packwiz-installer-bootstrap.jar http://localhost:8080/pack.toml
```

Every launch then syncs the mods from the served pack (a pack URL on GitHub Pages or raw content replaces localhost once the pack is hosted).

**Server (throwaway, for testing).** From an empty folder, with `packwiz serve` running:

```bash
PACK_URL=http://localhost:8080/pack.toml bash /path/to/pack/server/start.sh
```

The script installs the NeoForge server, downloads the bootstrap, syncs the pack's server side and starts the server, which stops at the Minecraft EULA: accept it by hand in `eula.txt` (never scripted), run the script again, then join `localhost` from the Prism instance.
