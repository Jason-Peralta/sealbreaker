# `sb:damage_class`

Datapack registry declared by `sb_core`; read by `sb_gear` (weapons name their class), `sb_combat` (which attribute scales a hit) and the class HUD. Files live at `data/<namespace>/sb/damage_class/<name>.json`. Loaded with the world; changes need a world reload, not `/reload`. There are exactly five, fixed by the PRD (3.2): melee, ranged, magic, summon, healing.

## Shape

```json
{
  "name": "melee",
  "attribute": "sb_core:melee_damage"
}
```

| Field | Type | Default | Meaning |
|---|---|---|---|
| `name` | string | required | Short name. The tooltip line and the class HUD read the lang key `damage_class.<name>` (`damage_class.melee`), so the same class name can be translated once and reused. |
| `attribute` | attribute id | required | The multiplier attribute of the class (`sb_core:melee_damage`, default 1.0). A weapon of this class multiplies its listed damage by the attacker's value of this attribute. Named by key, so an entry may point at an attribute a module registers later. |

## Entries

`sb_core` ships all five (`melee`, `ranged`, `magic`, `summon`, `healing`), generated by `./gradlew :sb_core:runData`. Content modules do not add damage classes; the class list is a design constant, not content.

## Read by

`sb_gear` (weapon items), `sb_combat` (damage), `sb_hub` (class display).
