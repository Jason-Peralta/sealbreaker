# 0022 — The rarity ladder, and one reforge pool per item family
Date: 2026-09-06
Status: accepted; refines the rarity list of `docs/02-prd.md` 3.12
Context: implementing the `sb:rarity` and `sb:reforge_pool` registries forced two choices the PRD left as a list of names. The PRD's ladder (Common, Uncommon, Rare, Epic, Legendary, Mythic) has no room for a *bad* outcome, but Terraria-style reforging is a gamble: a roll that can only improve an item is not a decision. The PRD also described one pool per archetype and class, which multiplies as archetypes grow.
Decision: the ladder is **bad (grey), common (white), rare (blue), epic (purple), legendary (orange)**, with a sixth **rainbow** rarity reserved for one-of-a-kind items; grey sits *below* white, so a reforge can leave an item worse and rerolling has a cost. The rainbow rarity's name cycles through the spectrum, with a static colour as the fallback for chat and logs; every rarity also carries an icon field so colour is never the only signal. Reforge modifiers live in exactly **four pools**: tools, melee weapons, guns (bows included), and magic (magic, healer and summoner items). A pool's membership is an item tag, and each tag is declared empty by `sb_core` and appended to by content modules.
Consequences: an item's pool follows from its tag, so a new weapon joins the right pool by adding one tag entry and never by touching Java; restrictions ("a spear cannot roll Broad") are expressed by which pool lists which modifier. Bad prefixes are ordinary entries with negative amounts and the grey rarity, so the reforge screen needs no separate concept for them and the no-repeat rule of PRD 3.5 matters more. `uncommon` no longer exists; anything that named it names `common` or `rare`. Rendering the rainbow name is a client concern the tooltip work must handle; until then it falls back to its static colour.
