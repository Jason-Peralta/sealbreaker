# 0020 — GeckoLib 5.5.5 for NeoForge 26.2, from the Modrinth Maven
Date: 2026-09-05
Status: accepted
Context: decision 0010 allows GeckoLib for boss and enemy animation and asks that the version and artifact coordinates be recorded when it is added. Spike S2 needed it on 26.2; GeckoLib 5.5.x has NeoForge 26.2 builds (5.5.1 to 5.5.5) on Modrinth, but its own Cloudsmith Maven has no 26.2 artifact, and the Modrinth Maven addresses versions by number or id, where the number 5.5.5 is shared by the Fabric, Forge and NeoForge jars.
Decision: `sb_bosses` depends on `maven.modrinth:geckolib:fTK5ltWI` (GeckoLib 5.5.5, NeoForge, 26.2) from `https://api.modrinth.com/maven`, declared as an `implementation` dependency so it is on every run's classpath; the version id lives in `sb_bosses/gradle.properties` (`geckolib_version_id`). The pack ships GeckoLib as its own mod through packwiz (Modrinth source), never bundled in our jars. Bumps follow the milestone version-bump policy and update this file's successor.
Consequences: every module that animates through GeckoLib depends on `sb_bosses` or declares the same coordinate (one place, `sb_bosses`, until a second module needs it, then the convention plugin); the mod id `geckolib` is a required dependency in `sb_bosses`'s mods.toml (`[5.5,)`); the game test server loads GeckoLib too, so entity tests run headlessly; a GeckoLib version bump is a one-line change plus a two-client capture run.
